# Devil's advocate audit — Gin Rummy

**Audited:** `main` @ `079ccc8` (Wave J) · prod `https://web-production-b2f62.up.railway.app` (walked live 2026-09-21) · read-only, no code changed.
**Method:** three code traces (reliability/queues · auth/billing/tenancy · scale/cost) with file:line evidence, a cold playtest on prod, a fixture-mode Playwright pass (axe WCAG 2A/AA + 390 px mobile), and re-verification of every headline claim by hand.
**Severity:** P0 = blocks launch to real users · P1 = hurts at 100–1k users · P2 = intuition/polish · P3 = debt.
**Note on model names:** the code's LLM tiers are named after another vendor's models (`LLM_MODELS.sonnet/haiku`); the backend is the configured provider. Below they are called "main tier" / "fast tier".

## Josh briefing — one page

**The product is not ready for real users, and the reasons are mostly not visual.** The last five waves made it *look* like a product; this audit is about what happens when a stranger with a credit card uses it.

1. **Nobody pays.** Every self-serve user is a workspace *owner*, and owners are hard-coded credit-exempt (`lib/credits-exempt.ts:24`). With the playtest bypass OFF, metering still never fires for the person who signed up. Only *invited* teammates would ever be charged. Revenue ≈ 0 while LLM/image spend scales with users. One-line fix, but every "metering is done" claim rests on it.
2. **The home screen can't do the job.** Coach at `/coach` is the product home, but at workspace level it can propose **no** tool (every builder returns `null` without a project — `lib/chat/orchestrator.ts:143-175`). On prod it answered "I'll generate 5 hooks…" and then produced nothing. Every Tools card (Hooks, Titles, Outline, Description) launches into that same dead end. A creator's first five minutes end in a promise the app can't keep.
3. **Success toasts lie in four more places.** Anything queued to the worker (Intel batch, avatar regen, titles/frames re-run, revision) toasts success and then polls for 5 minutes with "still working" — a failed or lost job is never surfaced (`components/lib/use-pipeline-poll.ts`, `components/ui/pipeline-note.tsx`). Wave H fixed exactly one instance of this pattern.
4. **The playtest door is a production hole.** `PLAYTEST_AUTH_BYPASS=true` is an unauthenticated sign-in as the product admin (`server/auth.ts:75-82`), callable from curl. Everyone is the same user; JWT sessions outlive the flag by 30 days.
5. **A Redis blip freezes the whole API.** `maxRetriesPerRequest: null` on the shared client (`queue/connection.ts:16`) means every request's rate-limit check awaits forever.
6. **The worker runs one job at a time** (`worker/index.ts:88-146`): one script generation, one sync, one ideas batch — product-wide. ~200 scripts/day ceiling; the nightly sweeps for a few thousand channels never finish.
7. **Mobile is broken.** Fixed 240 px rail on a 390 px phone leaves 150 px for content (verified). Creators are on phones.
8. **Thumbnails without S3 live in one web process's memory** and are gone on the next deploy; a second replica 404s. `S3_*` must be mandatory before launch; nothing ever deletes an S3 object.

Honest counterweight: tenancy is enforced everywhere sampled; secrets, OAuth tokens and cookies are handled well; the research fetcher has a best-in-class SSRF guard; credits are idempotent and never charged on failure; the F0 429-storm fix held on prod. **Tests are green (1019) and that proves the code does what the tests say — not that the product is safe.** None of the eight items above is covered by a test.

**Recommended order:** fix 1, 4, 5 in one day (three small diffs); then 2 (product decision: Coach must be able to create a project); then 3 + 6 + 8 (a week); then 7 and the polish list.

## Executive summary (scariest first)

- **BILL-01 (P0)** Workspace owners are credit-exempt → self-serve users are never metered.
- **UX-01 (P0)** Workspace-level Coach (the home) cannot execute any tool; every Tools card lands there. Verified on prod: "I'll generate 5 hooks" → nothing.
- **SEC-01 (P0)** `PLAYTEST_AUTH_BYPASS` = passwordless sign-in as admin, from curl; shared identity; JWT outlives the flag.
- **REL-01 (P0)** Redis outage hangs every API request (infinite retries on the shared client; rate-limit middleware on every procedure).
- **REL-04 (P0)** Queued jobs that fail or are lost are invisible; UI says "still working" for 5 min then goes quiet. Same class as the Wave H empty-board bug, in 5+ places.
- **REL-02 (P1)** Worker concurrency = 1 per queue; user jobs queue behind nightly sweeps.
- **DATA-01 (P1)** In-memory object storage on the web dyno; no S3 deletes ever; images served through Next with no CDN.
- **UX-02 (P1)** App shell unusable under ~900 px (150 px content column on a phone).
- **BILL-03 (P1)** `/api/chat-stream` runs an unmetered main-tier call for any `chat:read` role with a client-chosen message id, on the 100/min general bucket.
- **SEC-02 (P1)** Rate limits key on the *first* `X-Forwarded-For` hop; spoofable → free-tool LLM budget drain and magic-link spam.
- **REL-03 (P1)** Worker deploy/crash mid-job loses the job for good (stale-run gate + 2 attempts); script editor spins forever.
- **COST-02 (P1)** Coach resends the full thread every turn, unmetered, no window; long threads cost more per turn and eventually break.
- **SCALE-02 (P1)** YouTube quota breaker trips on sweeps; the tail of channels fails nightly with a red "failed" badge and no explanation.
- **UX-03 (P1)** Channels page is a three-way wizard (demo / paste handle + niche keywords / Google) when the intent is "show me my channel".
- **BILL-02 (P1)** Stripe webhook idempotency marker is written before processing; a handler error permanently drops the event.

## P0 — launch blockers

### BILL-01 · Owners are credit-exempt (metering is off for everyone who signs up)
- **Severity:** P0 · **Category:** Billing
- **Evidence:** `lib/credits-exempt.ts:24-25` `isRoleCreditExempt = role === "owner" || role === "admin"`; `server/routers/impl/workspace.ts:161-165` every `workspace.create`/`ensureDefault` inserts the caller as `owner`; `server/credits.ts:113` and `server/billing/overage.ts:96` return early on exemption; every pipeline passes `creditExempt: isCtxCreditExempt(ctx)` → `skipDebit` (`impl/script.ts:164`, `impl/thumbnails.ts:88`). `server/mcp/auth.ts:73` resolves API keys to the owner, so MCP is free too while `server/mcp/route.ts:32` tells agents it "charges workspace credits".
- **Why it fails:** the entire "pay per stage" story is a no-op for the buyer. 10 users ≈ $150/mo uncontrolled spend; 1k ≈ $15–60k/mo with $0 metered.
- **Fix:** exemption = `ADMIN_EMAILS` only (drop the role rule), or a per-workspace `billing_exempt` flag set by ops. Update the 4–5 tests that assume owner-exempt. · **Effort:** S (code) / M (tests + docs).

### UX-01 · The home screen (workspace Coach) cannot do the job; Tools cards lead into it
- **Severity:** P0 · **Category:** Product/IA
- **Evidence:** `lib/chat/orchestrator.ts:143,150,157,163,175` every tool builder returns `null` when `ctx.projectId === null`; `lib/chat/persona.ts:96` tells the model the same. Prod walk (`/coach`, 2026-09-21): "Give me 5 hooks for a tech explainer about phone batteries" → reply "I'll generate 5 hooks… Style isn't set yet, so they'll stay generic until we lock a voice." → no hooks, no proposal card, no next step. `components/toolkit/tools.ts:25-66` Hook/Title/Research/Outline/Description all `coachLaunchHref(...)` → `/coach` (workspace level). `COACH_STARTERS` (`components/chat/chat-panel.tsx`) seed prompts the same Coach can't fulfil.
- **Why it fails:** the first useful outcome (hooks) is unreachable from Coach or Tools without first discovering Projects → New project → channel → Generate. Also the reply is non-streamed (`llm.complete`, `server/chat/turn.ts:129`) so the user stares at an empty pane for 10–20 s before a sentence appears.
- **Fix:** give the workspace Coach a `create_project` tool (title from the request; channel = the only/selected one) and let intents chain "create project → make_hooks"; or route Tools cards to `/projects/new?intent=hooks`. Stream the reply (`llm.stream`). · **Effort:** M.

### SEC-01 · Playtest bypass = unauthenticated admin sign-in
- **Severity:** P0 · **Category:** Security
- **Evidence:** `server/auth.ts:75-82` Credentials provider, `credentials: {}`, `authorize()` unconditionally returns `resolvePlaytestUser()`; `:50` picks `ADMIN_EMAILS[0] ?? "joshbuse@hexbandit.io"`; only limiter is the spoofable 5/min "auth" IP bucket. `POST /api/auth/callback/playtest` with a CSRF token from `GET /api/auth/csrf` works from curl whether or not the button is shown. `server/credits.ts:83` makes *everyone* exempt while the flag is on. `:111` forces JWT sessions → existing sessions stay valid ~30 days after the flag is flipped off.
- **Why it fails:** one shared identity means shared workspaces, API keys, OAuth channel tokens, Stripe portal. Any URL leak = full admin.
- **Fix:** delete the provider before launch; until then refuse it in `lib/config.ts` superRefine when `NODE_ENV=production` unless an explicit `PLAYTEST_ALLOWED_HOSTS` matches; rotate `AUTH_SECRET` when it comes off. · **Effort:** S.

### REL-01 · Redis outage hangs every request
- **Severity:** P0 · **Category:** Reliability
- **Evidence:** `queue/connection.ts:16` `new Redis(REDIS_URL, { maxRetriesPerRequest: null })` (offline queue on, infinite retries) is shared by the rate limiter; `server/routers/_contracts.ts:73-77` puts `rateLimitMiddleware` on every procedure; `server/ratelimit/middleware.ts:235-256` "fail open on store errors" never runs because ioredis never rejects. Same for `queue.add()` in `pipelines/script/execute.ts:18`.
- **Why it fails:** at 10 users a Redis blip = all requests pending until the proxy times out; at 1k the Next process fills with hung requests.
- **Fix:** separate client for limiter/quota with `maxRetriesPerRequest: 2`, `enableOfflineQueue: false`, `commandTimeout: 500`; keep `null` only for the BullMQ worker connection; wrap `queue.add` in a timeout. · **Effort:** S.

### REL-04 · Failed/lost jobs are invisible; success toasts everywhere
- **Severity:** P0 · **Category:** Reliability/UX
- **Evidence:** `impl/_shared.ts:79-80` `jobAccepted()` returns `randomUUID()` unrelated to any run row. `components/lib/use-pipeline-poll.ts:69-83` polls 3 s for 5 min, stops only on data change; `components/ui/pipeline-note.tsx:25-30` then says "Still working — check back shortly". `ideas.requestBatch` doesn't even poll: `discovery-screen.tsx:124` toasts "Fresh concepts requested — they'll appear here in a moment" and nothing else. Worker failures go only to logs/Sentry (`worker/index.ts:163-169`); no procedure exposes failed `pipeline_runs`. Re-running titles/frames/revision/avatar with identical input is a silent no-op (hash has no nonce: `lib/types/pipeline.ts:460-463`, `pipelines/script/titles.ts:317`, `pipelines/revision/pipeline.ts:183`, `pipelines/avatar/pipeline.ts:248`) → "Regenerate" → spinner → nothing.
- **Why it fails:** every worker-side error reads as "the app is slow"; support can't correlate; this is the exact bug class Josh already hit twice (Intel batch, empty board).
- **Fix:** return a run/job id; add `pipeline.status` (latest `pipeline_runs` for project+kind) and stop the poll on `failed` with the error; nonce user-initiated re-runs (as `requestBatch` already does with `batchNonce`). · **Effort:** M.

## P1 — will hurt at 100–1k users

### REL-02 · Worker concurrency 1 per queue, single replica
- **Evidence:** `worker/index.ts:88,111,139` `new Worker(name, handler, { connection })` — no `concurrency`. The `sync` queue carries nightly channel sync, daily-ideas fan-out, outlier refresh, credit reconcile, avatar regen **and** user-triggered `ideas.requestBatch`/`avatar.regenerate`. `script` queue = one script at a time product-wide (5–7 min each).
- **Impact:** two people drafting at once → one waits minutes. 1k channels → daily-ideas alone ~4 h; user jobs queued behind it. 100k → sweeps never finish before the next fan-out.
- **Fix:** `concurrency` per worker (script 4–8, sync 8+), separate queue or `priority` for user-triggered jobs, jittered `delay` on fan-out. · **Effort:** S.

### REL-03 · Worker deploy/crash mid-job loses the job
- **Evidence:** `queue/pipeline-runner.ts:160-174` refuses a run while a `running` row is < 5 min old; nothing marks the row failed on crash; BullMQ `attempts: 2, backoff 5s` (`queue/queues.ts:40-41`) retries into `RUN_ALREADY_IN_PROGRESS` → failed set. Script SSE subscribers wait for a terminal event that never comes (`pipelines/script/events.ts:225-233`); `use-script-stream.ts:147-170` has no inactivity timeout.
- **Fix:** on BullMQ `failed`/`stalled`, mark active `pipeline_runs` rows failed and publish a terminal event; backoff ≥ claim freshness or bypass the gate for the same job id; client stall timer. · **Effort:** M.

### DATA-01 · Object storage: memory fallback, no deletes, no CDN
- **Evidence:** `server/storage/index.ts:39-48` silent `MemoryObjectStorage` fallback (one warning); boards generate synchronously in the web request (`impl/thumbnails.ts:129`) and store 3–6 × ~1 MB PNG + 2 MB reference in web memory; `registerS3StorageClient` **is** wired in both processes (`instrumentation.ts:12`, `worker/index.ts:74`) but `storage.delete` is never called by app code; `projects` cascade deletes rows, orphaning objects. `/api/thumbnail-image` buffers whole objects, `Cache-Control: private, max-age=300`, no ETag, sits on the 100/min general bucket — a 20-concept board view spends 20 % of the user's API budget.
- **Impact:** without `S3_*`: OOM after a few hundred boards, 404s on a second replica, wipe on deploy. With S3: unbounded growth.
- **Fix:** require `S3_*` when `PROVIDERS=live`; signed URLs or a CDN in front; delete objects on concept/project delete; exempt the image route from the general bucket. · **Effort:** M.

### UX-02 · Shell is unusable below ~900 px
- **Evidence:** fixture Playwright at 390×844: `aside` 240 px, `main` 150 px on `/coach`, `/discover`, `/projects`, `/toolkit/thumbnails` (message bubbles wrap one word per line). `components/shell/app-shell.tsx:58` `w-rail shrink-0`, no breakpoint.
- **Fix:** collapse the rail to a drawer under `md`; top bar gets a menu button; Coach composer full-width. · **Effort:** M.

### BILL-03 · Unmetered main-tier call from `/api/chat-stream` with viewer role
- **Evidence:** `app/api/chat-stream/route.ts:106` asserts `chat:read`; `:115-121` runs `runAssistantTurn` with `messageId` from the query string; `server/chat/turn.ts:129-134` main tier, 1200 out, full transcript; `impl/chat.ts:82` mints the id as a bare UUID nothing records; limit is `general` 100/min (`route.ts:65-69`). Zero credits by contract (`_contracts.ts:240-244`).
- **Fix:** pre-insert a `pending` assistant row in `sendMessage`, require it in the route, require `chat:create`, put the SSE open on the `generation` policy or its own bucket. · **Effort:** M.

### SEC-02 · Spoofable IP for every IP-keyed limit
- **Evidence:** `server/ratelimit/middleware.ts:142-147` takes `forwarded.split(",")[0]`. If Railway *appends* to `X-Forwarded-For` (standard), a client-supplied first hop yields a fresh bucket per request: `/api/tools` (fast tier, 5/day/IP, `app/api/tools/route.ts:19-20`), magic-link sends, the playtest callback. Client daily cap is honor-system (`components/tools/gate.ts:3-4`).
- **Fix:** use the last XFF hop / Railway's forwarded header; global per-route ceiling; daily budget on free tools. Verify Railway semantics first. · **Effort:** S.

### COST-02 · Coach resends the full thread every turn, unmetered
- **Evidence:** `server/chat/turn.ts:114,132` `listMessages` (no limit, `server/chat/store.ts:311-322`) → `buildTranscript(history)`; `lib/chat/context.ts:130` loads full research doc content every turn to count words.
- **Impact:** ~700 tok/exchange growth; a 30-message thread ≈ 15k tokens/turn; 200 messages ≈ 140k and eventually a hard context error → the thread is permanently broken. ~$12/user-month at 10 turns/day with no ceiling; an abusive free account ≈ $5/min.
- **Fix:** window last N turns + rolling summary; meter or daily-cap turns; select only `wordCount,title` for context. · **Effort:** M.

### SCALE-02 · YouTube quota: silent nightly failures at scale
- **Evidence:** sync 3 units/channel (`pipelines/sync/pipeline.ts:104-118`); outlier refresh `search.list` 100 units × ≤6 keywords per keyword set (`pipelines/ideation/outliers.ts:115-129`); budget 9 000 (`quota.ts:26`) shared in Redis — good — but `QuotaExceededError` inside a stage is retried 3× + BullMQ 2× and the channel is marked `failed` (`sync/pipeline.ts:214-220`) with no rotation; `ideation/compete.ts:87-90` and `server/voice/train.ts:119-120` call the provider without `quota.charge`.
- **Impact:** ~3 000 channels exhaust the budget before any outliers; beyond that the same tail fails every night with a red "failed" badge (the trust-killer Josh already saw on the demo).
- **Fix:** no retry on quota; rotate order by `lastSyncedAt`; cadence by activity; key rotation; charge compete/train; explain "failed" in UI. · **Effort:** M.

### UX-03 · Channels is a wizard, not "my channel"
- **Evidence:** prod `/channels` with nothing connected shows three competing paths (demo · paste handle + "Niche keywords, up to 6" · Verify with Google) before any value; Intel's empty state sends you here. Niche keywords are asked before the product has shown a single insight.
- **Fix:** one input ("Your channel URL or @handle") → connect → Intel; niche keywords inferred from the channel's titles (already in `channel_videos`) and editable later; demo as a small text link. · **Effort:** M.

### BILL-02 · Stripe webhook marker written before processing
- **Evidence:** `server/billing/events.ts:334-336` `recordEventOnce` then `switch`; `app/api/stripe/webhook/route.ts:50-53` 500 on throw → Stripe retries → `duplicate: true` → never reprocessed. Ledger writes are per-event keyed, but `plan`, `stripeCustomerId`, `billingPeriodEnd` updates are not.
- **Fix:** marker inside the handler's transaction, or delete the marker on failure. · **Effort:** S.

### REL-06 · Retries resume into fixture/placeholder content in live mode
- **Evidence:** `pipelines/script/pipeline.ts:349` `state.outline ?? params.presetOutline ?? synthOutline(context)` — a BullMQ retry after the outline stage is done (and charged) drafts from a synthetic outline; `pipelines/research/pipeline.ts:66` `synthQueries` on resume; `pipelines/avatar/pipeline.ts:184-189` invalid LLM JSON → `deterministicAvatar` in live mode, still charged.
- **Fix:** persist stage output to `pipeline_runs.output` and rehydrate on resume; throw instead of `synth*` when `mode !== "fixture"`. · **Effort:** M.

### OPS-01 · Without `REDIS_URL` prod silently degrades
- **Evidence:** `server/ratelimit/middleware.ts:63-68` per-process limiter; `pipelines/script/execute.ts:17-21` generation runs inline in the web request. `lib/config.ts` requires neither `REDIS_URL` nor `S3_*` in production.
- **Fix:** superRefine: `REDIS_URL`, `S3_*` required when `NODE_ENV=production && PROVIDERS=live`. · **Effort:** S.

### BILL-04 · Unmetered live provider paths
- **Evidence:** `script.regenerateSection` (`impl/script.ts:216`), `frame.propose`, `description.generate`, `tags.generate`, `ideas.whyItWorked`, `ideas.searchDemand` (`impl/ideas.ts:192-200`), `research.importTranscript` (`impl/research.ts:66-82`, no `generation` limiter), `ideas.competitorCompare` at `ideaBatch: 0`; thumbnails use `requireCredits` not `requireCreditsWithOverage` (`impl/thumbnails.ts:74,119,156`).
- **Fix:** meter or per-workspace daily caps; consistent `generation` policy. · **Effort:** M.

## P2 — UX intuition / polish

### UX-04 · Intel "feels empty" for a public channel, by design
- **Evidence:** the Analytics block lists five N/A tiles; for a `@handle` channel the honest numbers (views/likes/comments/subs) are the whole story. Prod today: Intel empty state → Connect YouTube → wizard (UX-03).
- **Fix:** collapse the N/A block into one line with a "connect Google to unlock" link; lead with the uploads table when there are videos.

### UX-05 · Jargon before payoff
- "StyleCard", "crossover", "niche keywords", "outlier ratio", "12.9× channel median", "composition pattern", "preset (from project)", "subject slot" appear on first screens (`/toolkit/ideas`, `/toolkit/thumbnails`, `/channels`). Fixture chat seed still says "(1 credit)" (`lib/fixtures` chat thread) — visible in the playtest.
- **Fix:** plain labels ("Style", "Blend two styles", "Topics you cover", "×your usual views"); scrub fixture copy.

### UX-06 · Nav mental model: Ideas vs Coach vs Intel vs Tools
- Coach also "does ideas" (starter chip), Ideas is a Tool, Intel is named like a research feed but is stats, Channels isn't "my account", "Projects" isn't "Videos". Six sections for one user job.
- **Fix:** rename Projects → Videos; Intel → My channel; Channels folds into Settings once one channel is connected; Tools grid keeps only surfaces that aren't Coach prompts (Thumbnail Studio, Ideas).

### UX-07 · Duplicate CTAs
- Projects shows "New project" twice (top bar + header); Coach shows "New chat" twice. One is enough.

### UX-08 · Non-streamed Coach reply
- `server/chat/turn.ts:129` uses `complete`, not `stream`; the client shows typing dots for the full provider latency (10–20 s on prod), then the whole reply at once. Streaming exists in the provider (`grok.ts:111`).

### UX-09 · Accessibility
- axe WCAG 2A/AA: all routes clean except `/toolkit/thumbnails` — `nested-interactive` (serious): the dropzone `role="button"` contains a `<button>` (`components/packaging/reference-dropzone.tsx:101-143`). Colour-only status: Intel verdict badges carry text (good); insight bullets are colour-only dots (minor).

### REL-10 · Chat deadline covers only the LLM call
- `withTurnDeadline` wraps `llm.complete` only (`server/chat/turn.ts:128-138`); context/DB reads are unbounded; the turn ignores `req.signal` so a closed tab doesn't cancel the provider call; the client has no wall-clock stall timer. Good: terminal `error` is emitted on provider error/timeout and on generator throw.

### REL-11 · Rate-limit buckets
- `chat.sendMessage` shares the 100/min `general` bucket with every read (`_contracts.ts:240-241`); `generation` fails **closed** on store error with "Rate limit exceeded" (`middleware.ts:239-250`) — during a Redis fault users are told they're rate-limited; the Redis sliding window is 4 non-atomic commands (`limiter.ts:116-122`).

### REL-12 · Masked / generic errors
- `server/trpc.ts:35-42` masks INTERNAL_SERVER_ERROR without a request id; research/titles/frames/revision/sync toasts are fixed "try again" strings regardless of code (`research-panel.tsx:116-118`, `titles-panel.tsx:37-39`, `editor-screen.tsx:188-199`); only thumbnails and ideas branch on the code.

### SCALE-03 · Boards block a web request for up to 120 s × N fal calls
- `board.ts:426-462` `Promise.all` inside the tRPC mutation; per-concept runner has 3 attempts on `generate_images` — a download failure after a successful render re-bills the provider (cost small: ~$0.14/board).

### COST-03/04 · Script pipeline token shape
- Every section prompt resends the 30k-token research block + script-so-far (`prompts/sections.ts:141-142`); no prompt caching; a JSON parse failure on section 8 regenerates 1–7 (`pipeline.ts:403-444`, no per-section checkpoint); fact-check sends *untrimmed* doc content per section (`pipeline.ts:527-541`) — 5 PDFs × 8 sections can exceed the context window and fail after the expensive stages ran.
- Per-user-month model (main $3/$15 per M, fast $0.20/$0.50, fal $0.023/img): Coach-only ≈ $13 · Coach + 2 scripts + 2 boards ≈ $17 · heavy ≈ $61. Starter is $49/60 credits — margins are fine **only if BILL-01 is fixed and Coach turns are metered or capped**.

### COST-05 · Daily ideas for every channel regardless of activity
- `pipelines/ideation/jobs.ts:118-129` → `listAllForSweep()` → one main-tier call per channel per night (~$0.90/channel/mo) for churned and free users alike.

### TEN-01 · `niche_videos` is a global index writable by any tenant
- `pipelines/ideation/store.ts:241-256` overwrites `niche_keywords` on conflict with the last writer's keywords; `connectDemo` upserts fixture videos globally in prod (`impl/channel.ts:270-275`). Public data only, no PII — but one tenant can retag what another sees. No GIN index for `arrayOverlaps` (`store.ts:262`).

### SEC-03/04, SSRF-01 · Small hardening
- `trustHost: true` (`server/auth.ts:116`) — set `AUTH_URL`; provider error bodies logged verbatim (`grok.ts:24`) — truncate/strip; `defaultFetchBytes` follows redirects with no private-IP check (`pipelines/thumbnails/pipeline.ts:81-89`; URL comes from fal, not users) — route through the existing `guardedFetch` (`pipelines/research/ssrf.ts`).
